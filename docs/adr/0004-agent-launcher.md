# エージェント起動は実行型ランチャーとコード内プロファイル表に一元化する

エージェント種別(ADR 0002)の起動差分は、これまで司令塔プロンプト内の散文分岐として存在していた。起動 argv の組み立ては入力が揃えば完全に決定論的であり、「決定論的に判定できる処理はプロンプトに埋めずスクリプトへ切り出す」(AGENTS.md)の適用漏れだった。第 3 のエージェント CLI(codex, amp 等)の追加を見据え、起動を単一のランチャーコマンドとコード内プロファイル表に一元化する。

## Decision

- **実行型ランチャー** `launch-agent` を追加する。司令塔は作業担当またはレビュー担当の起動時にこのコマンドだけを呼ぶ。ランチャーはプロファイルからエージェント固有の引数列を組み立て、**シェルを介さず**（`execFile` 相当）Herdr 0.8.0 の `agent start <name> --kind <kind> --pane <root-pane> -- <native argv>` を実行し、結果をそのまま返す。実行ファイルは `--kind` が選ぶため、`--` より後へ `pi` や `claude` 自体を含めない。引数列を印字して司令塔にシェル展開させる案は、数段落の日本語プロンプトを含む引数の引用を LLM の記述精度に依存させるため退けた。
- ランチャーへ渡すペインは、`worktree create/open` が返し、所属する実行場所、最初のタブ、正規化した作業ツリーパスとの一致を確認したルートペインに限る。ランチャーはタブ作成、ペイン分割、同名の担当の終了処理、配置の推測を行わない。試行用の実行場所の取得と破棄はライフサイクル ADR に従う。
- **プロファイル表は `src/agent-profiles.cjs` のコード内型付きテーブル**とし、エージェント種別の列挙検証(`normalizeProject`)もここから導出する唯一の情報源にする。operator 設定によるプロファイル拡張は認めない(ADR 0002 が自由記述テンプレートを退けたのと同じ理由: エージェント追加は promise 遵守・入力の癖・前提条件の検証を伴う PR 作業)。
- プロファイルは**前提条件**(claude の workspace trust 等)を宣言し、ランチャーが起動前に fail-fast 検査する。未充足が確定 → 起動せず解決コマンド付きエラー。判定不能 → 警告して続行(trust ダイアログは既知の突破手段があるため、不確実な検査で止めるほうが害が大きい)。判定関数は doctor と共有する。
- **セッション識別フラグはプロファイル任意項目**とする。`pi` は `--name`、`claude` は `--session-id` を取るが、`omp` に相当するフラグは無い。Herdr が `agent start <NAME>` で担当名を持つため、CLI 側の識別は起動の必要条件ではない。識別フラグを持たない CLI では argv から省き、保存先指定などの別用途フラグを識別子として流用しない(流用すると本来の意味とずれ、試行ごとにセッションファイルが散る)。
- **実装言語は TypeScript**(node で直接実行、type stripping が使えない環境では CommonJS + JSDoc 型に切替)。core.ts との情報源共有・vitest ネイティブテスト・型検査が理由。あわせて「**新規の決定論ヘルパーは TypeScript を第一言語とし、既存 Python ヘルパーは大きく変更する機会に個別に移行判断**」を方針とする(一括書き直しはしない)。
- **モジュール形式はファイル拡張子で宣言する**。`module.exports` を書く実行時モジュールは、型注釈を使う場合 `.cts`、使わない場合 `.cjs` とし、ホストの拡張ローダーが読むモジュールグラフでは `.ts` を ESM 専用に保つ(`node` の子プロセスとして起動するだけの実行スクリプトはローダーを通らないため、この制約の対象外)。ランチャーとドライバーはビルド手順なしで `node` から直接実行でき、`require` で相互に読み込む CommonJS のままだが、ホストの拡張ローダーは中身ではなく拡張子でモジュール形式を判定する(omp の拡張ローダーは `.cjs` / `.cts` 以外の TypeScript を必ず ESM として読む)。拡張子で宣言しない場合、同じファイルがホストによって CommonJS と ESM に分かれ、`module is not defined` で拡張全体のロードが失敗するか、`require` が空の名前空間を返して関数が `undefined` になる。判断の記録は `docs/omp-host-portability-prd.md`。
- スコープは「エージェントを起動する」操作のみ。督促・メッセージング(pane 送信)は別の継ぎ目であり、含めない。将来の実行基盤追加(tmux 等)はこのランチャーに `--runner` 相当を足す形で受ける。

## Consequences

- 司令塔プロンプトからエージェント別の起動コマンド分岐(散文)が消え、テンプレートは実行基盤・エージェント非依存の 1 コマンド呼び出しになる。
- pr-reviewer テンプレートも同じランチャーを使うため、レビューエージェントの claude 対応(#31)は「設定値 `reviewerAgent` を追加して渡すだけ」に縮む。
- エージェント追加の手順が定形化される: プロファイル 1 エントリ + プロトタイプ検証(ADR 0002 の 4 項目)+ テスト、を 1 つの PR で。
