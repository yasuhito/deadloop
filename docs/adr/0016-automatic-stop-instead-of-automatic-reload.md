# ADR 0016: 更新を自動で取り込まず、自動で停止する

## Status

Superseded by [ADR 0035](0035-code-reload-at-the-tick-boundary.md). コード識別子の定義、未コミットの変更を含めないこと、走っている試行を殺さないこと、停止中も status と doctor が動くことは ADR 0035 に引き継がれた。「自動停止」の決定だけが「tick 境界での自動取り込み」に置き換わった。

## Context

deadloop は pi 拡張として working tree から直接ロードされる。実行コードは各 pi セッション起動時のスナップショットであり、長寿命のオーケストレータ間でコード世代が混在する。checkout が更新されても、走っているオーケストレータは古いコードのまま動き続ける。

2026-08-11、別リポジトリの pi セッションで動いていた古いコードのオーケストレータが、共有 enablement 状態を旧スキーマで書き戻し、`automationLogin` を消し続けた。PR reviewer は認証済み identity が automationLogins に無いとして停止した。復旧は古いセッションでの手動 `/reload` だった。operator には、どのセッションが古いのか、いつ壊れたのかを知る手段が無かった。

手動 `/reload` に頼る運用は、忘れた瞬間に静かに壊れる。`autoMerge` を有効化すると人間がマージに立ち会わなくなるため、この失敗は悪化する。

## Considered options

**自動リロード。** 更新を検知したら拡張が自分でコードを読み直す。採らない。安全なリロードには「全試行ゼロの静止点」の検知が必要で、deadloop を積む全セッション（他リポジトリを含む）の協調が要る。rolling upgrade の難問を抱え込む。誤ると進行中の試行の足元でコードが入れ替わる。

**手動リロードのみ。** 現状維持。採らない。忘れた瞬間に古いコードが黙って共有状態を壊す。2026-08-11 の事故がそれである。

**自動停止。** 更新を検知したら止まり、人間に `/reload` を促す。採用する。deadloop の fail closed の考え方に合致し、静止点の検知を必要としない。

## Decision

Automation host が実行しているコードを **コード識別子** で表す。値は deadloop checkout の commit とする。ロード時に確定し、そのプロセスが生きている限り変わらない。内容ハッシュ、ファイル更新時刻、`package.json` の version は採らない。内容ハッシュは開発中の編集すべてに反応して停止を多発させ、ファイル更新時刻は戻した編集と進めた編集を区別できず、`package.json` の version は実際に動いていない。

未コミットの変更はコード識別子に含めず、停止の理由にもしない。未コミットのコードが実行されないことは、ADR 0017 のコードスナップショットを commit から作ることで構造的に保証する。dirty 判定は行わない。

ロード済みの識別子と配備中の識別子が食い違うとき、共有 enablement 状態の書き込みと、tick で automation を選ぶ処理を fail closed で止める。読み取り、status 表示、doctor 診断は停止中も動かし、人間に理由と復旧手順を伝える。

走っている試行は殺さない。停止の目的は「新しい副作用を始めさせない」ことであり、「走っているものを止める」ことではない。全 guarded operation を止める案は採らない。進行中の試行を途中で殺し、未公開の commit を実行基盤の worktree に残すためである。走っている試行の契約を守るのは ADR 0017 の責務とする。

判定は純粋関数に閉じ込め、git と fs の観測は注入する。配備中識別子の取得元は ADR 0017 の段階で git 以外へ変わるため、判定関数の入力形は取得元に依存させない。

共有 enablement 状態に、最後に書いた Automation host のコード識別子を記録する。診断のためだけに使い、判定には使わない。判定に使うと、古いセッションが読み取りごと停止して status を出せなくなり、人間に理由を伝えられなくなる。

## Consequences

- operator が `git pull` で deadloop のコードを取り込んだ直後、deadloop を積む全セッションが停止する。復帰は各セッションでの `/reload` となる。これは意図した動作である。
- deadloop のコードを編集しただけでは何も止まらない。deadloop で deadloop を開発できる。
- ファイル更新時刻による既存の鮮度警告と、その文言、関連テストを削除する。未コミットの編集で発火するため、本決定と矛盾したことを言い続ける。
- doctor 診断の禁止事項から「オーケストレータセッション自身の設定鮮度診断」を外し、「他セッションが実行中のコードの断定」を加える。doctor は共有状態に残った足跡から推定できるが、他セッションがロードしたコードを知ることはできない。
- tick が止まる間、詰まった試行の後始末が `/reload` まで遅れる。既存の reconciliation が後から拾う。
- 本決定は敵対的な Worker からの防御を主張しない。ADR 0015 が定めた協調モデルの範囲を超えない。
