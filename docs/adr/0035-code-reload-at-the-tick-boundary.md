# ADR 0035: 更新を tick 境界で自動で取り込み、取り込めないときだけ停止する

## Status

Accepted. [ADR 0016](0016-automatic-stop-instead-of-automatic-reload.md) を supersede する。ADR 0016 が導入したコード識別子、未コミットの変更を識別子に含めないこと、走っている試行を殺さないこと、停止中も status と doctor が動くことは、本 ADR に引き継ぐ。用語: `CONTEXT.md` の「コード更新の取り込み (Code reload)」。

## Context

ADR 0016 は、deadloop checkout の commit が進んだとき Automation host を止め、人間に `/reload` を促す決定だった。自動リロードを退けた理由は三つで、「全試行ゼロの静止点」の検知が要る、deadloop を積む全セッションの協調が要る、誤ると進行中の試行の足元でコードが入れ替わる、だった。

その後の決定が三つとも解消した。ADR 0017 でエージェントはコードスナップショットから動き、ホストのコード世代と無関係になった。ADR 0029 で試行監視はモデル無しの決定論的な再配信になり、引き渡しは `state.json` に残るので、ホストを読み直しても次の tick が拾う。ADR 0032 でワークフロー状態は GitHub に置かれ、ローカル資源は証拠になった。識別子ガードは古いセッションの書き込みを止めるので、他リポジトリのセッションとの協調も要らない。

残ったのは運用の詰まりである。deadloop で deadloop を開発すると、PR をマージして main を進めるたびにホストが止まり、人が `/reload` を打つまで次の試行が始まらない。人が忘れれば止まったままになる。ADR 0016 が「忘れた瞬間に静かに壊れる」ことを嫌ったのと同じ理由で、「忘れた瞬間に静かに止まる」ことも避けたい。

Pi は `ctx.reload()` をコマンドハンドラに提供し、拡張からは `pi.sendUserMessage("/command", { expandPromptTemplates: true })` でコマンドを起動できる。reload は `session_shutdown` を経由し、deadloop の `stopScheduler` は実行中の tick を待ってから終わる。`session_start(reason: "reload")` でスケジューラは自動で再開する。

## Decision

tick の冒頭で、ロード済みのコード識別子と配備中の識別子が食い違い、セッションが空いている（`isIdle` かつ未処理メッセージ無し）なら、ホストは `/deadloop-reload` を自分に送り、拡張を読み直してスケジューラを再開する。これを「コード更新の取り込み」と呼ぶ。

同じ配備識別子に対して取り込みを頼むのは一回だけとする。頼んだあとも古いままなら、停止して「取り込みを頼んだが新しくならなかった。`/deadloop-reload` で確かめよ」と表示する。新しい配備識別子が現れれば、また一回だけ頼む。壊れたコミットを読んだときの挙動は、一回失敗して止まり理由が status に出る、という ADR 0016 と同じ fail closed の形に収まる。

セッションで人が会話中なら頼まない。止まった状態で待ち、空いた次の tick で頼む。待つ間も新しい副作用は始めない。

ホストは自分の checkout を書き換えない。main を進める（`git pull`）のは人の操作であり、ホストは進んだ checkout に追随するだけである。ホストは開発 checkout から動いてよく、コミットやブランチ切り替えのたびに取り込みが起きる。未コミットの編集では何も起きない。

判定は純粋関数 `decideCodeReload` に閉じ込め、セッションの状態と識別子の観測は注入する。tick の途中で識別子が食い違った場合は、従来どおり止まるだけで取り込みは頼まない。取り込みは tick の入口だけで起きる。

## Considered options

**自動停止のまま（ADR 0016）。** 採らない。deadloop で deadloop を進める経路が人の `/reload` で詰まる。

**通知だけ足す。** 採らない。人を待つ時間は残る。

**30 秒ごとに何度でも頼む。** 採らない。壊れたコミットのとき 30 秒ごとに失敗が積もる。一回だけ頼む JustOnce の形にする。

**会話中でも即座に取り込む。** 採らない。人が打った `/deadloop-doctor` の途中で reload が割り込む。

**ホストが origin/main を fast-forward で追う。** 本 ADR では採らない。開発 checkout で人が作業している最中にファイルが足元で変わる。ホスト専用 worktree を用意する判断と一緒に、別の ADR で扱う。

## Consequences

- PR をマージして `git switch main && git pull` すれば、30 秒以内にホストが新しいコードで続く。人の操作はそこまでで、`/reload` は要らない。
- 開発 checkout をホストにしている間は、コミットやブランチ切り替えのたびに取り込みが起きる。未マージのブランチで実地確認する運用はそのまま成り立つ。
- スケジューラを持たないセッション（deadloop を積んでいるが enable していない）は取り込まない。書き込みもしないので害はない。
- `/deadloop-reload` は人が手で頼む入口でもある。status と doctor の復旧手順は `/reload` から `/deadloop-reload` に変わる。
- ADR 0033 の「識別子ガードが tick を拒むので、tick が走るときホストのコードとスナップショットは同じ commit」という前提は変わらない。拒んだ tick が取り込みを頼み、次の tick は新しいコードで走る。
