# ADR 0027: 生存は存在の有無で判定し、状態値から寿命を導かない

## Status

採用済み。[ADR 0020](0020-stop-proving-work-authority.md) が実行基盤に委ねた問いの中身を定める。supersede しない。

[ADR 0020](0020-stop-proving-work-authority.md) は「試行が動いているかを答える権威は実行基盤だけ」と定めたが、実行基盤に**何を尋ねるか**は書かなかった。実装は Herdr の `agent_status` を寿命の答えとして読み、`working` 以外を終了と分類した。Herdr の意味論では `idle` / `done` / `blocked` は「ターンを終えて次の入力を待っている」状態であり（`herdr agent wait` が既定で待つのはこの 3 つ）、プロセスの終了ではない。結果として、起動直後の試行とターンを終えた試行が「所有者が停止した」と判定され、生きている試行の権限が解放されて PR が停止した。PR #331（2 回）、#346、#348 で観測した。

## Decision

実行基盤に尋ねるのは「その試行が名前で指すエージェントが一覧に存在するか」だけとする。存在しなければ**担当者不在**、存在すれば生存であり、状態値は寿命の判定に使わない。エージェントの同一性が読めない場合（同じ checkout に別のエージェントが居る、同名が別 checkout に居る）は従来どおり判定不能として失敗側に倒す。

## Consequences

- 誤判定は構造的に起きない。存在の有無は 1 ビットで、実行基盤が新しい状態値を追加しても再分類の判断が要らない。
- 担当者不在に依存する 3 経路（workspace の後片付け、試行の引き継ぎ解放、完走した試行の引き渡し）の発火が遅くなる。対話モードのエージェントはターン後も終了しないため、これらはエージェントが実際に居なくなるまで動かない。平常時の完了と後片付けは監視経路が promise ファイルを見て担うので、この 3 つは回復専用の経路として残る。
- 入力待ちのまま完了報告を出さずに放置された試行は、自動では回収されない。`/deadloop-doctor` の保持試行の所見として人が見る。待ち打ち切りの自動化は別の作業とし、しきい値を権限調停と監視の 2 系統で数えることは避ける。
- `authorityRelease.reason` は完走しなかった終わり方の 3 値になる。`owner_absent`、`never_launched`、`superseded_by_request`。完走は phase（`workspace_closed`）で表すため、理由名は持たない。
- 旧 `github_authority_lost` を持つ試行記録は読めなくなる。保存状態のための後方互換処理を持たない方針（AGENTS.md）に従い、正規化も移行経路も置かない。旧記録は完了した試行の終端記録であり、deadloop は所有権を手放した試行を飛ばすためにしか読まないため、削除する。手順は `extensions/deadloop/README.md` に置く。
- 担当者不在で完走の引き渡しが拒否された場合は、`completion_handoff_refused` として停止理由を分ける。担当者不在を理由に挙げると、PR に投稿済みのレビュー結果と食い違う説明が並ぶ。
