# Herdr の実行画面を試行ごとに使い捨てる

## Context

Git の作業ツリーは PR が完了するまで残す必要がある一方、作業担当やレビュー担当の端末は一つの試行が終われば引き継ぐ必要がない。従来は作業ツリーの実行場所にタブとペインを追加し、完了後も同名の担当を残していた。このため、完了済みの端末が活動中に見え、後続のレビューや修正が一つの実行場所に積み上がった。

Herdr 0.7.5 は既存の利用可能なシェルペインを `agent start --pane` で対象にし、配置を変更しない。これに合わせ、永続的なブランチ状態と使い捨ての実行画面を分離する。

## Decision

- 対応する Herdr は安定版 0.7.5 以上とする。自動化の実行元は起動時と各周期の先頭で、クライアント、接続先、通信の互換性を確認する。候補選定や GitHub、作業ツリー、実行場所、担当の変更より前に、非対応状態を拒否する。
- 作業担当、レビュー担当、レビュー修正担当、ブランチ更新担当の各試行は、作業ツリーを一つの新しい実行場所として開き、その最初のタブとルートペインだけを使う。後続の試行は同じ Git 作業ツリーを別の新しい実行場所と端末で開く。
- 起動意図は、最初の外部変更より前に、起動ごとに固有の実行記録ディレクトリにある `attempt.json` へ原子的に保存する。記録には試行、役割、対象、入力リビジョン、ブランチ、予定作業ツリー、担当名、プロンプト、完了ファイル、実行場所、タブ、ルートペイン、単調に進む段階を結び付ける。
- 担当名は `dl-<role>-<target>-<hash12>` とし、起動 UUID を含む入力から決定的に生成する。同名の完了済み担当を終了して再利用しない。
- 完了ファイルは V1 の強い報告に限り、記録済み試行との試行 ID、役割、リポジトリ、対象、入力リビジョン、役割別証拠を照合する。従来形式は読み取れても実行場所を閉じる根拠にしない。
- 役割ごとの GitHub 結果を再取得して確認した後だけ `github_persisted` を記録し、`herdr workspace close` だけを実行する。実行場所が消え、作業ツリーとブランチが残ることを確認して `workspace_closed` とする。
- 遮断、人間による判断待ち、従来形式、欠落や破損、起動失敗、GitHub への保存未確認、所有権不明の実行場所は調査用に残す。実行場所が残っている作業ツリーでは次の試行を起動しない。
- 実行場所を閉じる処理の時間切れや結果不明は後片付け待ちとし、push、PR 作成、コメント、ラベル変更、レビュー、マージを繰り返さない。再起動時の照合も同じ証明だけを使い、冪等にする。
- `worktree remove` は試行の後片付けに使わない。マージ済みまたは終了済み PR の既存安全条件だけが作業ツリーを削除できる。`/deadloop-doctor` は診断だけを行う。

## Consequences

活動中の一試行は Herdr 上で一つの実行場所、タブ、ペインとして見える。成功結果を GitHub に引き渡した後は実行画面だけが消え、ブランチと作業ツリーは次の試行または PR 完了まで残る。

移行時は先に新規起動を止め、旧試行を終了または意図的に遮断し、`autoMerge: false` を再確認してから deadloop を導入する。その後 `herdr update --handoff` を実行し、`/deadloop-doctor` と自動マージしない動作確認用 Issue で、実行場所が消えて作業ツリーが残ることを確認する。旧形式または所有権不明の過去の実行場所は自動回収しない。

詳細な判定表と停止条件は [Disposable Herdr workspace lifecycle](../herdr-attempt-workspace-lifecycle-spec.md) を正とする。
