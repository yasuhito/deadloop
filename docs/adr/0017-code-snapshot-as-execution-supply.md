# ADR 0017: 実行コードは working tree ではなくコードスナップショットから供給する

## Status

Accepted

## Context

一つの試行の途中で deadloop の checkout が更新されると、オーケストレータが開始時に使ったコードと、Worker がプロンプト内の絶対パスから後に起動する automation スクリプトのコード契約が混在する。

PR #217 で実際に発生した。オーケストレータは旧コードで修復試行を開始し、finding count を持たない旧形式のマーカーを GitHub に記録した。修復担当の作業中に checkout が切り替わり、新しい finalizer が実行された。新しい finalizer は finding count を必須とするため、修復 commit 作成後、必須検証と push の前に汎用の invariant failure で停止した。未公開の修復 commit が実行基盤の worktree に残り、PR に `agent:blocked` が付いた。Issue #225 として記録されている。

ADR 0016 の自動停止は「新しい試行を始めさせない」ことしかできない。すでに始まった試行は tick の外で進むため、別の仕組みが要る。

依存パッケージも可変である。`tsx` の入れ替わりは型の解釈を変え、`yaml` の入れ替わりは設定の読み方を変える。どちらも黙って効く。

## Considered options

**識別子の照合のみ。** 試行開始時のコード識別子を記録し、automation スクリプトが起動時に照合して、食い違えば止める。コードは複製しない。採らない。Issue #225 の受入条件は満たせるが、試行が完走しない。止まった試行には `agent:blocked` が付き、人間が後始末をする。`autoMerge` 有効化後はその人間が居ない。

**試行ごとの複製。** 試行を開始するたびにパッケージを複製する。採らない。automation スクリプトの大半が共通の内部モジュール群を読み込むため、複製の単位は実質パッケージ全体になる。試行は 1 日に何十回も走るため重すぎる。

**コード識別子ごとの複製。** 採用する。複製は checkout の commit が動いたときだけ発生し、試行はそれを指すだけになる。長期の配備形態と同じ成果物になるため、二つの仕組みを作らずに済む。

## Decision

**コードスナップショット** を導入する。一つのコード識別子につき一度だけ作られる、読み取り専用の deadloop パッケージ複製である。試行はこれを指して開始から完了まで同じコードで動き、Automation host はこれを読み込んで起動する。

中身はそのコード識別子の commit から作る。working tree からの複製は採らない。working tree が dirty なとき、中身と識別子が食い違い、同じ識別子で異なる中身の複製が競合するためである。この結果、未コミットの変更は実行されない。

作成は自動とし、automation を起動する直前に、無ければ作る。同じ識別子の二回目以降は作らない。人間の事前準備を必要とする方式は採らない。忘れた瞬間に壊れる手順は、ADR 0016 が解こうとしている失敗を別の形で作る。作成または依存の確保に失敗した場合は automation を起動しない。

依存パッケージもコード識別子の一部として扱う。lock ファイルの内容ハッシュごとに固定し、ハードリンクで複製する。ネットワークは使わない。スナップショットごとのインストールは採らない。失敗しうる処理を試行の開始経路に入れることになる。

置き場所は Automation host の状態ディレクトリ配下とし、ADR 0010 が定めた run ディレクトリと同じ階層に置く。

試行の記録にコード識別子を保持し、プロンプトに埋め込まれる automation スクリプトの絶対パスはコードスナップショット配下を指す。識別子の照合も併用し、automation スクリプトが起動時に供給元の識別子と試行の記録を照合して、食い違えば外部副作用と修復 commit 作成の前に更新不整合として停止する。照合の権威は Automation host が持つ記録側に置き、Worker が変更できる作業領域内のコードを権威にしない（ADR 0015）。

pi の package 参照を、可変な working tree から固定名の配備先へ向ける。**working tree 直ロードを廃止する。** 新しいコードの配備は明示コマンドとし、そのコマンドが対象 commit のコードスナップショットを作り、配備先を張り替える。自動での切り替えは採らない。人間の知らないうちに新しいコードが本番へ入るためである。

古いコードスナップショットを自動では削除しない。参照が無くなったことの判定には deadloop を積む全セッションの試行を横断して見る必要があり、これは ADR 0016 が自動リロードを退けたのと同じ難問である。誤ると走っている試行の足元のコードを消す。世代数の上限で消す方式も、長く走っている試行が溢れて消えるため採らない。doctor 診断が世代数と容量を報告し、掃除コマンドを提示する。消すのは人間が判断する。

## Consequences

- working tree が実行経路から完全に外れる。deadloop のコードを編集しても、走っているオーケストレータと試行に何も起きない。
- ADR 0016 の配備中識別子の取得元が git から配備先へ変わる。判定に git を必要としなくなる。判定関数そのものは変更しない。
- pi 設定の切り替えは一度きりの人間作業となる。対話式ウィザードで案内する。
- 配備コマンドを打つまで新しいコードは動かない。忘れると古い世代のまま動き続けるが、その状態は世代が揃っており安全である。
- コードスナップショットの世代が溜まる。1 世代あたりのコードは小さく、依存はハードリンクのため実質増えない。掃除は operator の判断で行う。
- 本決定の導入時点で走っている試行は救済しない。本決定の後に開始する試行から適用される。
- ADR 0003 が定めた promise の完了報告契約、ADR 0010 の実行成果物の隔離、ADR 0015 の権威の所在は変更しない。

## ADR 0033 による追記(2026-08-28)

本 ADR の「working tree 直ロードを廃止し、配備コマンドで配備先を張り替える」は実装されていない。Automation host は `extensions/deadloop/index.ts` をロード時の checkout から読み込み、`deployedIdentity` は checkout の `HEAD` である。ホストのコード世代のずれは ADR 0016 の識別子照合(ロード時識別子 ≠ checkout の HEAD なら tick を開始しない)が防いでいる。

コードスナップショットの役割は、エージェントが自分の session 内で実行するスクリプト(`run-project-check`、`pr-review-repair-finalize`、`pr-branch-update-finalize`)の供給元である。ホストが実行する処理(driver、reconciler、完了ハンドラ)はホストの読み込み済みコードを in-process で呼ぶ。tick の開始が許される限り、両者は同じコード識別子である。エージェント向けの絶対パスは引数で渡される供給元(`supply.automationDir`)から作り、`__dirname` からは作らない。
